# FIRE Calculator · 复利实验室

人民币与美元双账户的资产走势、退休生活费和复利模拟器。纯 HTML、CSS 与 JavaScript，无框架依赖，无后端。

**在线使用：[huzhe01.github.io/fire-calculator](https://huzhe01.github.io/fire-calculator/)**

## 三个视图

- **Dashboard**：查看人民币和美元的原币余额、折合人民币的合计资产、今天购买力及累计生活费。拖动年份查看各时点余额。
- **退休支取**：模拟退休前月末投入、退休后生活费、通胀、汇率、美元向人民币分批补充，以及生活费缺口。展示资产、年度或累计支取曲线和逐年明细。
- **单账户复利**：调整本金、定投、投资年数和逐年收益率，对比固定收益路径，并计算累计盈利、几何年化与资金加权年化（IRR）。

Dashboard 与退休支取共用参数；单账户复利保留独立设置。数值可输入或拖动。美元逐年收益率圆点支持鼠标、触屏及方向键。

## 本地运行

需要 Python 3；运行检查和测试还需 Node.js 22 或更高版本。不需要安装 npm 依赖。

```sh
git clone https://github.com/huzhe01/fire-calculator.git
cd fire-calculator
python3 -m http.server 4176 --directory dist
```

打开 [localhost:4176](http://localhost:4176)。不要直接通过 `file://` 打开 HTML，浏览器需要通过 HTTP 加载 ES modules。

也可以使用 `npm run dev` 启动同一个服务。

检查包含脚本语法、模块与静态资源引用，以及 GitHub Pages 子路径兼容性。模型测试覆盖：

## 双账户模型

美元账户单位为万美元，人民币账户、生活费和净转入单位为万元人民币，汇率为每美元兑换多少人民币元。

每个月按顺序计算：

1. 退休后，根据策略检查人民币储备；必要时转出美元，扣除换汇成本并计入人民币账户。
2. 从人民币账户支付当月生活费。不足部分记为缺口，不允许透支，也不自动滚为未来债务。
3. 两个账户分别获得当月投资收益。年度收益按几何复利平均分摊至月度。
4. 未退休时，把年新增本金的 1/12 在月末分别计入账户；退休后两边同时停止新增。

“10 年后退休”表示完整积累 10 年，从第 11 年第 1 月开始支取。生活费每年按通胀调整一次，年内按相同月预算支取。

生活费模式从今天购买力出发，计算退休时及之后的预算。起点比例模式用退休开始时的两账户合计资产确定第一年预算，再按通胀增长，不是每年重新按最新余额取固定比例。

储备不足模式触发后，会按频率分批补到目标。固定金额模式把年度人民币净额按频率分摊。实际补充同时受每次上限、每年上限和美元可用余额约束；这些上限是模拟参数，不代表法规或实际渠道限额。

**月末总资产 = 月初总资产 + 外部新增本金 + 投资收益 + 汇率估值变化 − 换汇成本 − 实际生活费。**

账户间转移不计作收入、新增本金或生活费。模型允许生活费消耗本金；不测算资本利得税或真实跨境到账延迟。

## 发布

GitHub Actions 在推送到 `main` 时执行检查和测试，成功后将 `dist/` 发布到 GitHub Pages。也可以在 Actions 中手动运行 **Deploy GitHub Pages**。

## 数据与限制

所有计算在浏览器内完成。页面不连接真实金融账户，不执行交易或转账，输入也不会上传或保存；刷新后恢复默认值。模型是单条指定收益路径的情景分析，不提供统计意义的退休成功概率。

在支持 WebMCP 的浏览器中，页面可通过 `get_compound_scenario`、`configure_compound_scenario`、`get_retirement_scenario` 和 `configure_retirement_scenario` 与助手交互；不支持时正常使用网页。WebMCP 的真实浏览器注册与调用未在当前发布环境中验证。
